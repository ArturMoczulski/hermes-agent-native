# Independent work and thinking cadence

## Starting from a purpose

Creating an agent with a purpose starts its work immediately; it does not wait
for the human to supply a task list or for the next scheduled check-in. The human
can begin with a broad instruction such as “develop a source of income for me.”

The agent's first work is to assess its understanding of itself, its purpose,
constraints, and available capabilities. It identifies what it knows, what it
can investigate, and which questions need an owner answer. This discovery is
part of working, not a separate setup exercise the human must complete first.

The agent develops an initial plan using project-management skills and follows
it. It starts clear, authorized work while asking necessary questions about
uncertain parts. It must not mechanically ask “what should I do?” when it can
propose a sensible plan itself. When the purpose is too unclear to choose useful
work, asking a focused question is the appropriate first action.

Plans and projects translate purpose into work that can be attempted, assessed,
revised, and completed. Plans evolve as the agent learns. Changes to the soul
follow ownership rules; self-discovery is not permission for self-redefinition.

For ongoing areas of work, the agent can organize a persistent team. An agent
running a company might identify the need for marketing, sales, delivery,
strategy, and leadership, then create children with those responsibilities and
their own cadence. It chooses which roles are useful within its authority,
rather than requiring the human to specify an organization chart.

## A thinking cadence

Each agent can have a configurable cadence: for example, every minute or once
a day. At each check-in, it considers:

1. Its purpose and applicable constraints.
2. New messages, answers, results, and relevant changes.
3. Progress of its projects and delegated work.
4. Work already underway and dependencies still outstanding.
5. Whether its purpose still needs work, including recurring obligations and
   the current [purpose evaluation](01-agents.md#lifetime-and-work-assignment).
6. Useful next actions, including independent work that can proceed in parallel.

It then chooses to continue, start work, delegate, revise a plan, ask a question,
propose a direction, wait, or initiate retirement when purpose evaluation supports
that outcome. Its decision and resulting work state must remain
available for the next check-in.

The cadence creates an opportunity to think. It does not require a new task,
a new child, or a human-facing message every time. It also does not mean that
the agent is continuously making decisions between check-ins.

## Choosing what comes next

When the next step is clear and authorized, the agent can proceed independently.
When important information is missing, it asks for clarification. When no next
step is apparent, it proposes what would be best to work on next. A proposal
requires an answer when direction or permission is missing; announcing an already
authorized step does not create an approval requirement. See
[questions and permissions](05-human-interaction.md#questions-proposals-and-permission).

Finishing a task or milestone does not automatically finish an ongoing purpose.
This applies to children as well as roots: a marketing child can initiate new
campaigns without waiting for its parent to assign each one. Every agent uses
[purpose evaluation](01-agents.md#lifetime-and-work-assignment) to distinguish
useful next work, continuing operations, waiting and a fulfilled purpose. It need
not propose more projects when its purpose has been fulfilled.
An enduring purpose does not justify busywork. The agent should connect
its proposed work to the purpose and explain why that work is worth doing.

## Active and blocked work

Before starting work, the agent checks whether it is already being performed.
If its producer is recording a song, another cadence tick must not start a
duplicate recording of the same assignment.

The agent can still examine independent branches. It might work on another
composition or delegate artwork research while recording continues. Parallel
work must respect dependencies, shared resources, and granted authority.

A blocked task does not necessarily block the whole agent. The work record
identifies what is missing and who is expected to resolve it. Questions follow
[the parent escalation chain](05-human-interaction.md): each parent answers or
passes the question upward; only an unresolved question reaching a root goes to
the human. The question remains pending while independent work may continue.

An unanswered question is not a new question at every check-in. The agent must
avoid repeated identical requests and must not treat silence as an answer. It
looks for other authorized work; if none is useful, it waits. Reminder timing
is a configurable interaction policy whose defaults remain open.

## Events and continuity

Human messages, answers, and child results must be received and retained between
check-ins as well as during work. The human must be able to interrupt an agent
without waiting for its next scheduled check-in.

**Proposed:** an answer or result that resolves a dependency makes the agent
eligible to reconsider its work promptly, rather than waiting for a distant
daily check-in. Repeated cadence ticks while it is busy can be combined into
one pending review; messages and results must not be lost.

After an interruption or restart, the agent must recover its purpose, plans,
active work, unanswered questions, and delegation relationships. If it is unclear
whether an action completed, recovery must examine the outcome before repeating
it. A restart is not evidence that the work never happened.

The human can inspect what the agent is doing, why it is waiting, and what is
expected to let it proceed. Useful progress means outcomes and learning, not
merely a count of activities.

## Detecting activity without progress

The framework detects patterns suggesting that work is not advancing: repeated
unsuccessful attempts, repeated plan changes without new results or learning,
and assignments passed between agents without resolution. It compares activity
with the intended outcome and recorded progress, rather than treating frequent
check-ins or tool use as success.

A detected pattern becomes an inspectable concern with the affected work and
supporting events. The responsible agent reviews it and records a response:
continue with a reason, change approach, investigate a blocker, or escalate
through the parent chain. Detection alone must not automatically retire an agent
or change its purpose.

Legitimate waiting, exploration that produces useful learning, and long-running
work must be distinguishable from repetition without progress. Uncertain cases
are flagged for review rather than presented as proven failure. The timing and
criteria for detection remain to be specified for different kinds of work;
the capability itself is required. Recurring concerns remain linked so a new
check-in does not produce an unrelated duplicate alert.
